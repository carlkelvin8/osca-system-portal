# OSCA System — Session Summary

## Objective
Build equipment borrowing with static QR workflow for Staff, attendance reports (daily/weekly/monthly) with export, facility quantity validation, a complete Audit Logs module (Admin-only), and a Venue Reservation Requests system (Coach/PE Instructor request, Admin/Director/Staff approve) — for ADMIN, DIRECTOR, and STAFF roles only (plus Coach/PE Instructor for reservations).

## Important Details
- Docker containers: `osca_api`, `osca_frontend`, `osca_postgres`, `osca_redis`, `osca_minio`, `osca_celery`, `osca_celery_beat`, `osca_nginx`
- RBAC: `_STAFF_BORROW_ROLES = {ADMIN, DIRECTOR, STAFF}` for new borrow endpoints
- Transaction QR format: `TXN-{id_hex[:12].upper()}` — auto-generated, unique, invalidated on completion
- Static QR (BorrowingID) format: `BID-{instructor_uuid}` — auto-generated on Coach/PE Instructor creation, permanent, never expires
- Static QR (BorrowingID) scan returns full coach/PE instructor info: eligibility, active borrows, pending requests, active sanctions
- Alembic head: `f3g4h5i6j7k8` (add cancelled to request_status_enum). Chain: `0e82300a6c8d` → `1a2b3c4d5e6f` → `f2b253e4d908` → `d61caf6ffd94` → `e7f8a9b0c1d2` → `f3g4h5i6j7k8`
- Attendance reports export via CSV (built-in `csv`), XLSX (`openpyxl`), PDF (`xhtml2pdf`)
- Facility `capacity` field: backend `ge=0` in Pydantic schema, frontend `min="0"` on number input, explicit validation message "Quantity cannot be less than 0."
- Equipment creation no longer renders/upload QR images — uses `EQ-{uuid_hex[:12].upper()}` as simple code
- User communicates in Taglish (Tagalog + English)
- Coach nav (ACTUAL state): coach STILL has Reports, Analytics, Facilities, Eligibility, Incidents, Sanctions + Attendance, Player Roster, Attendance Scan (`/kiosk`). The "Coach nav alignment" note below was NOT implemented — user chose to defer it ("iwan muna").
- Coach attendance is scoped to `assigned_sport` (coaches' `sport_or_art` is NULL — use `assigned_sport` in frontend/backend sport checks for coaches).
- `GET /attendance/records`: accepts `date_from`, `date_to` query params; returns `session_name`, `session_sport_or_art`; students auto-filtered to own records
- **Audit Logs = ADMIN-only** (backed up by `_EDITOR_ROLES = {UserRole.ADMIN}` in `backend/app/api/v1/audit_logs.py` + frontend nav gate). Director/Staff get 403.
- **Audit context capture**: `get_current_user`/`get_optional_user` in `core/dependencies.py` attach `user._current_request = request`; `audit_log()` service (`services/audit_service.py`) auto-falls back to `request_of(current_user)` when no explicit `request` is passed → every log captures IP + browser + OS + device + URL + method.
- **Audit call sites** now use the `audit_log()` service (NOT inline `AuditLog(...)`): auth (login success/failed, logout, password change), users (register/update/deactivate/delete/profile picture/face enroll), attendance (session create/update/end, face scan time-in/out, FR consecutive-fail alert), inventory (equipment create/update, borrowing ID issued, request create/approve/release/reject/cancel/delete, borrow/return/staff-borrow/release-complete), announcements (create/update/delete/image), facilities (create/update/schedule), eligibility (create/update), incidents (create/update), sanctions (create/update/acknowledge), reports (generate/export), system (FR config update), audit (log viewed).
- Audit Logs page (`dashboard/audit-logs/page.tsx`): Admin-only guard, search, module/action/status dropdowns (from `/audit-logs/filters/*`), date range inputs (`date_from`/`date_to`), newest-first sort toggle, pagination, detail modal with JSON diff (previous/new values), CSV/XLSX/PDF export. Nav link "Audit Logs" (`ScrollText` icon) added to `dashboard/layout.tsx` with `roles: ["admin"]`.
